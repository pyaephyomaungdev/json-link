# JSON Link Vite i18n Integration Skill

This skill guides AI agents and developers on how to seamlessly integrate translations managed in **JSON Link** into any React + Vite application with compile-time type safety, zero external library overhead, and instant Vite Hot Module Replacement (HMR).

---

## Core Principles

1. **Zero-Daemon, Zero-Overhead**: No local watch daemons or Swagger/API servers. The integration relies strictly on static JSON bundles and Vite's native module bundler.
2. **Compile-Time Type Safety**: Keys are strongly typed via `translations.d.ts` so developers get full IDE autocomplete and compile-time detection of typos or deleted keys.
3. **Drop-in First**: Prioritize dropping `/src/locales/` into the developer's existing repository over forcing them to clone an entire boilerplate app.
4. **Token & ICU Preservation**: Interpolation preserves `{variable}` and Mustache tokens without mangling formatting or punctuation.

---

## Architecture: The Drop-In Locales Structure

When exported from JSON Link as a Vite Starter, the complete translation bundle resides in `src/locales/`:

```
src/
└── locales/
    ├── en.json              # Source language dictionary
    ├── my.json              # Target language dictionary (Myanmar, etc.)
    ├── translations.d.ts    # Autogenerated TypeScript definitions (keys & langs)
    ├── i18n.ts              # Reactive client loader (~120 lines, 0 dependencies)
    └── devtools.tsx         # In-App Devtools Drawer (live copy inspection & tweaking)
```

### 1. `translations.d.ts` (Type Definitions)
Defines `SupportedLanguage` and `TranslationKey` string unions based on all keys currently in the spreadsheet:

```typescript
export type SupportedLanguage = "en" | "my";

export type TranslationKey =
  | "app.title"
  | "auth.welcome"
  | "common.cancel";

export interface TranslationDictionary {
  [key: TranslationKey]: string;
}

export type I18nResources = {
  [lang in SupportedLanguage]: Record<TranslationKey, string>;
};
```

### 2. `i18n.ts` (Reactive Client Loader)
A clean, zero-dependency client loader that exposes:
- `t(key, params?, lang?)`: Core translation function with `{param}` interpolation and dotted key traversal (`auth.login.title`). Works for both flat and nested JSON.
- `updateTranslation(key, value, lang?)`: Updates in-memory dictionary and notifies subscribers.
- `setLanguage(lang)`: Global active language updater.
- `getLanguage()`: Returns active language.
- `useTranslation()`: React hook for functional components.
- `import.meta.hot.accept()`: Native Vite HMR listener that updates text on the screen without full page reloads.

### 3. `devtools.tsx` (In-App Devtools Drawer)
Self-contained React component (`<JsonLinkDevtools />`) providing:
- Floating launcher button (`JSON Link Devtools`) at the bottom corner.
- Slide-over inspection drawer with live search filter across all translation keys.
- Language switching tabs to compare translations side-by-side.
- Live in-memory copy editing with zero backend/daemons required.
- 1-click clipboard copy (`Copy JSON`) and direct file download (`Download JSON`).

## Agent Integration Recipes

### Recipe 0: Automated Setup via `create-jsonlink` (1-Command)

**For an existing React + Vite project:**
In your project root, run:
```bash
npx create-jsonlink
```
This automatically configures `@jsonlink/vite-plugin` in `vite.config.ts`, creates `src/locales/` (`en.json`, `my.json`, `translations.d.ts`, `i18n.ts`), and mounts the interactive spreadsheet dashboard at `http://localhost:5173/__jsonlink` with direct two-way disk saving and instant HMR.

**For a brand-new localized React app:**
```bash
npm create jsonlink my-app
# or
npx create-jsonlink my-app
```

### Recipe 1: Dropping into an Existing React + Vite Project

When asked to add localization or connect JSON Link to an existing React project manually:

1. **Verify or create `src/locales/`**:
   Ensure `src/locales/` exists and contains the exported `.json` files and `i18n.ts`.

2. **Verify `tsconfig.json`**:
   Ensure `resolveJsonModule` is enabled:
   ```json
   {
     "compilerOptions": {
       "resolveJsonModule": true
     }
   }
   ```

3. **Wire up in React components (3 lines)**:
   ```tsx
   import { useTranslation } from './locales/i18n';

   export function NavigationBar() {
     const { t, language, setLanguage, languages } = useTranslation();

     return (
       <nav>
         <span>{t('app.title')}</span>
         <select
           value={language}
           onChange={(e) => setLanguage(e.target.value as any)}
         >
           {languages.map((lang) => (
             <option key={lang} value={lang}>
               {lang.toUpperCase()}
             </option>
           ))}
         </select>
       </nav>
     );
   }
   ```

### Recipe 2: Handling Interpolated Variables

For translation strings containing dynamic variables like `Welcome back, {username}!`:

```tsx
// In locale JSON: { "auth.welcome": "Welcome back, {username}!" }
const { t } = useTranslation();
<p>{t('auth.welcome', { username: user.name })}</p>
```

### Recipe 3: Updating / Syncing Locales

When new translation strings are added or updated in JSON Link:
1. Export updated JSON files from JSON Link (or export the Vite Starter ZIP).
2. Overwrite files in `src/locales/`.
3. Vite HMR will immediately refresh the copy in active browser tabs with zero server restarts.

### Recipe 4: Mounting the `<JsonLinkDevtools />` Drawer for In-App Live Copy Tweaking

When developers or QA want to inspect, search, and tweak copy directly inside their running Vite app without touching source files:

1. **Mount `<JsonLinkDevtools />` in your root `App.tsx` or layout**:
   ```tsx
   import { JsonLinkDevtools } from './locales/devtools';

   export default function App() {
     return (
       <div>
         <MainContent />
         {/* Devtools Drawer for live in-app inspection */}
         {import.meta.env.DEV && <JsonLinkDevtools />}
       </div>
     );
   }
   ```

2. **In-Browser Inspection & Tweaking**:
   - Click the floating **JSON Link Devtools** button in the bottom corner.
   - Filter translation keys by key name or copy content in real time.
   - Switch language tabs (e.g. `EN`, `MY`, `JA`) to review translations side-by-side.
   - Edit any string in the textarea: `updateTranslation()` updates the in-memory dictionary and dispatches to `useTranslation()` subscribers, immediately re-rendering the running app's UI.
   - Click **Copy JSON** or **Download JSON** to export updated dictionaries back into your project.

### Recipe 5: Adding a New Language Manually or via Agent

When requested to add support for a new language (e.g. Japanese `ja`):

1. Create the locale JSON file:
   `src/locales/ja.json`:
   ```json
   {
     "app.title": "こんにちは世界"
   }
   ```
2. Register the language in `src/locales/translations.d.ts`:
   ```typescript
   export type SupportedLanguage = "en" | "my" | "ja";
   ```
3. Import and wire in `src/locales/i18n.ts`:
   ```typescript
   import ja from './ja.json';

   export const SUPPORTED_LANGUAGES: SupportedLanguage[] = ['en', 'my', 'ja'];
   export const resources: Record<SupportedLanguage, Record<string, any>> = {
     en,
     my,
     ja,
   };
   ```

### Recipe 6: Persisting User Selected Language

To persist user language across page reloads without external state managers:

```tsx
import { useTranslation, SupportedLanguage } from './locales/i18n';
import { useEffect } from 'react';

const STORAGE_KEY = 'app_locale';

export function LanguageSelector() {
  const { language, setLanguage, languages } = useTranslation();

  // Load saved preference on mount
  useEffect(() => {
    const saved = localStorage.getItem(STORAGE_KEY) as SupportedLanguage | null;
    if (saved && languages.includes(saved)) {
      setLanguage(saved);
    }
  }, [languages, setLanguage]);

  const handleChange = (newLang: SupportedLanguage) => {
    setLanguage(newLang);
    localStorage.setItem(STORAGE_KEY, newLang);
  };

  return (
    <select value={language} onChange={(e) => handleChange(e.target.value as any)}>
      {languages.map((l) => (
        <option key={l} value={l}>{l.toUpperCase()}</option>
      ))}
    </select>
  );
}
```

## Agent Verification & Quality Checklist

Before completing any localization task:

- [ ] **Typecheck Verification**: Run `npx tsc --noEmit` to verify all `TranslationKey` usages match `translations.d.ts`.
- [ ] **No Unused Imports**: Ensure `import React from 'react'` is not left unreferenced if React 19 JSX transform is active.
- [ ] **Devtools in Dev Mode**: Guard `<JsonLinkDevtools />` with `import.meta.env.DEV` to ensure 0 bundle size impact on production builds.
- [ ] **Dot Notation Resolution**: Keys with dots (e.g., `auth.login.title`) work automatically whether the JSON is formatted as flat keys or nested objects.
